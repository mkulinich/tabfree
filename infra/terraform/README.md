# TabFree AWS infrastructure (OpenTofu / Terraform)

OpenTofu modules for TabFree on AWS (ADR-009) and the `sandbox` environment for Phase 0 task P0.4.

> **Warning: `apply` creates billable AWS resources.** With the defaults, the sandbox costs roughly $80–100 a month even when idle (see [Cost](#rough-monthly-cost-sandbox)). Run it only in a dedicated sandbox account, and tear it down when you are done.

## Layout

```
infra/terraform/
  modules/
    network/      VPC over 2 AZs (or 3), public and private subnets, optional single NAT gateway, S3 gateway endpoint
    lake/         S3 buckets (raw, lake, Athena results), Glue database, Athena engine v3 workgroup
    metadata_db/  Aurora PostgreSQL 17 Serverless v2, password managed in Secrets Manager
    redshift/     Redshift Serverless namespace and workgroup (optional)
    compute/      ECS cluster (Fargate and Fargate Spot), ECR repositories, app security group, log group
    extract_converter/  Fargate task definition and least-privilege IAM roles for `convert-batch` (P2.8)
  envs/
    sandbox/      Root module that wires the modules together
```

## What the sandbox creates

| Area | Resources | Notes |
|---|---|---|
| Network | VPC `10.40.0.0/16`; 2 public `/24` and 2 private `/20` subnets; internet gateway; **one** NAT gateway (`enable_nat_gateway`, default on); S3 gateway endpoint (free) | The default security group is stripped of all rules. Not highly available: one NAT gateway in one AZ. |
| Lake | Buckets `tabfree-sandbox-{raw,lake,athena}-<account>-<region>` | All buckets: public access blocked, ACLs disabled, SSE-S3 (or SSE-KMS via `kms_key_arn`), TLS-only bucket policy, incomplete uploads aborted after 1 day. Raw bucket: versioning on, old versions expire after 90 days. Results bucket: objects expire after 7 days. |
| | Glue database `tabfree_sandbox`, location `s3://<lake bucket>/warehouse/tabfree_sandbox/` | Iceberg tables go here. |
| | Athena workgroup `tabfree-sandbox` | Engine v3, settings enforced (clients cannot override them), results in the results bucket (encrypted), per-query bytes-scanned cutoff (default 10 GiB), CloudWatch metrics. |
| Metadata DB | Aurora PostgreSQL Serverless v2 cluster `tabfree-sandbox-metadata`, one `db.serverless` writer, database `tabfree` | Newest available 17.x minor version, chosen at creation. 0.5–2 ACU by default. Private subnets, not publicly accessible, storage encrypted. Master password generated by RDS and kept in **Secrets Manager**. Port 5432 open only to the app security group. 7-day backups, PostgreSQL logs exported (30-day retention), deletion protection on. |
| Redshift (off by default) | Serverless namespace and workgroup `tabfree-sandbox-redshift` | `enable_redshift = true`. Base capacity 4 RPU (the minimum). Private, enhanced VPC routing. Admin password in Secrets Manager. Port 5439 open only to the app security group. |
| Compute | ECS cluster `tabfree-sandbox` (Fargate capacity providers); ECR repositories `tabfree/{api,worker,author,snapshot,converter}`; app security group; log group `/ecs/tabfree-sandbox` | ECR: scan on push, immutable tags, untagged images expire after 7 days, newest 30 images kept. The app security group allows only HTTPS out, plus 5432/5439 to the databases; it has no ingress until a load balancer is added. |
| Extract converter | Task definition `tabfree-sandbox-converter` (Fargate, linux/amd64, 4 vCPU / 16 GiB, 200 GiB ephemeral storage, read-only root file system, uid 10001); task and execution IAM roles | `enable_extract_converter`, default on; costs nothing until a task runs. Task role: read `blobs/` and `downloads/` in the raw bucket; read and write (no delete) `staging/` and `warehouse/<db>/` in the lake bucket; Athena in the one workgroup and its `results/` prefix; Glue create, update and drop tables in the one database. Execution role: pull from the `converter` repository, write to the ECS log group. |

Not created yet (later phases): IAM roles for the other services, ALB, Cognito, SQS, EventBridge Scheduler, SES identities, WAF, VPC flow logs, CloudTrail. The sandbox is deliberately small and not highly available.

## Deploy

Prerequisites: OpenTofu 1.10+ (developed with 1.12.3) or Terraform 1.10+, and credentials for the **sandbox** account only.

```sh
cp infra/terraform/envs/sandbox/terraform.tfvars.example infra/terraform/envs/sandbox/terraform.tfvars   # optional; edit
tofu -chdir=infra/terraform/envs/sandbox init
tofu -chdir=infra/terraform/envs/sandbox plan -out=tfplan
tofu -chdir=infra/terraform/envs/sandbox apply tfplan     # creates billable resources
tofu -chdir=infra/terraform/envs/sandbox output
```

Set `allowed_account_ids` in `terraform.tfvars` so the provider refuses to run against any other account.

State is **local** by default (`envs/sandbox/terraform.tfstate`, gitignored, and not shared). For a shared sandbox, use the commented S3 backend in `envs/sandbox/versions.tf` (S3-native locking, no DynamoDB) and run `init -migrate-state`. Commit `.terraform.lock.hcl`; `.terraform/` is gitignored.

Get the database password from Secrets Manager (`metadata_db_secret_arn` output). Never copy it into files.

### Teardown

Deletion protection and non-empty buckets block `destroy` on purpose. To remove the sandbox:

1. Set `aurora_deletion_protection = false` and `force_destroy = true` in `terraform.tfvars`, then `apply`.
2. Run `tofu -chdir=infra/terraform/envs/sandbox destroy`.

A final snapshot named `tabfree-sandbox-metadata-final` is kept unless `aurora_skip_final_snapshot = true`. Delete it before destroying a recreated cluster again.

### Manual step: Amazon Bedrock model access (Claude)

Bedrock model access can't be fully managed in Terraform, so do this once per account and region:

1. In the Bedrock console for the sandbox region, open **Model access** (or **Model catalog**). Make sure the Anthropic Claude models you need are available. For Anthropic models, AWS requires a one-time use-case form per account before first use.
2. Bedrock subscribes the account through AWS Marketplace on first invocation, so the first caller needs `aws-marketplace:Subscribe` (or an admin can enable the models first). SCPs or IAM policies can then limit which model IDs are allowed.
3. Check from a sandbox shell: `aws bedrock list-foundation-models --by-provider anthropic --region us-east-1`, then one small `bedrock-runtime converse` call.
4. Later, task roles for the API and author sandboxes need `bedrock:InvokeModel` / `bedrock:InvokeModelWithResponseStream` on the chosen model or inference-profile ARNs. Calls from private subnets reach Bedrock through the NAT gateway, or through a `bedrock-runtime` interface endpoint if you add one.

AWS has changed this console flow several times (2025–2026), and these steps were not re-checked when this was written. Follow the current Bedrock documentation if they differ.

## Rough monthly cost (sandbox)

These are estimates at us-east-1 list prices, based on the research notes (`docs/research/notes/aws_architecture_ai_authoring.md` §4). They are not quotes.

| Item | Default | Est. $/month |
|---|---|---|
| NAT gateway | 1 × $0.045/h + public IPv4 + ~20 GB | **~35–40** |
| Aurora Serverless v2 | 0.5 ACU floor × $0.12/ACU-h + ~10 GB storage | **~45** |
| S3, Glue Catalog, ECR, CloudWatch Logs | small volumes | ~1–5 |
| Athena | $5/TB scanned; capped at 10 GiB per query | usage only |
| Redshift Serverless (if enabled) | 4 RPU × $0.375 = $1.50 per *active* hour; nothing when idle | usage only |
| ECS cluster | no charge until tasks run | 0 |
| **Idle total** | | **≈ $80–90** |

NAT and the Aurora floor dominate. The plan's estimate for a small (50-user) production install is about $275 a month for infrastructure plus Claude tokens (BUILD_PLAN ADR-009); that estimate includes Fargate services, an ALB and more.

For a cheaper idle sandbox, set `enable_nat_gateway = false` (Fargate tasks in private subnets then can't pull images or reach AWS APIs) and `aurora_min_capacity = 0` (the cluster pauses after an hour idle; the first connection after a pause waits about 15 seconds or more). Together these bring idle cost to roughly $5 a month.

## Notes and known gaps

- **Provider:** `hashicorp/aws ~> 6.0` (locked to 6.73.0, the latest on 2026-11-20). The modules use v6 attribute names such as `data.aws_region.current.region`.
- **Redshift subnets:** AWS documents Redshift Serverless as needing subnets in three AZs. The network defaults to two, so enable Redshift together with `az_count = 3`. A plan-time check warns if you don't. This requirement was not re-verified in Nov 2026.
- **Aurora version:** the cluster takes the newest 17.x minor at creation and then ignores `engine_version` drift, letting automatic minor upgrades apply. Major upgrades need a deliberate change.
- **Encryption:** AWS-managed keys by default. Every module takes an optional `kms_key_arn` for customer-managed keys (production should use one, see P7.3).
- **Validation done:** `tofu fmt`, `init -backend=false` and `validate` pass, and a mocked `tofu test` plan (no AWS calls) passed. Nothing has been applied to a real account, so AWS-side constraints (quotas, service-specific rules) are untested.

## Running the extract converter (P2.8)

Build and push the image from `infra/docker/converter/Dockerfile` (tag it with the git SHA and set `converter_image_tag`), then fan out with one task per shard. Each task reads the raw store's `downloads/manifest.json`, converts its share, and writes `staging/extracts/<sha256>/` in the lake bucket; re-running a shard skips what is done.

```sh
for i in 0 1 2 3; do
  aws ecs run-task --cluster tabfree-sandbox --launch-type FARGATE \
    --task-definition "$(tofu -chdir=infra/terraform/envs/sandbox output -raw converter_task_definition)" \
    --network-configuration "awsvpcConfiguration={subnets=[<private-subnet-ids>],securityGroups=[<app-sg>],assignPublicIp=DISABLED}" \
    --overrides "{\"containerOverrides\":[{\"name\":\"converter\",\"command\":[\"convert-batch\",\"--workers\",\"2\",\"--shard\",\"$i/4\"]}]}"
done
```

The task role cannot delete objects and is limited to one Glue database and one Athena workgroup. `convert-batch` writes the Athena DDL and Glue parameters into each report but does not run them yet. None of this has run against AWS.
