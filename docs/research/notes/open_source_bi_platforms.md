# Open-source BI / dashboard platforms and AI-native (LLM-authored) dashboard tools as foundations for, or existing equivalents of, "TabFree"

*Snapshot date: 2026-11-20. Star counts, licenses, last-push and latest-release dates were pulled from the GitHub REST API (`gh api repos/OWNER/REPO`, `.../releases/latest`) on that date; feature facts come from each project's own docs/source files (mostly read directly from the repos) plus vendor pricing pages. "n/v" = not verified in this session.*

## 1. Platform-by-platform comparison (license, activity, backing, Athena/Redshift, RBAC/RLS, SSO, scheduling, embedding, as-code, custom HTML/JS, Tableau import, AWS, AI/MCP)

### Takeaway
Only Apache Superset combines a permissive license (Apache-2.0, ASF-governed, no open-core gating), live Athena + Redshift querying, built-in RBAC + row-level security, OAuth/LDAP SSO, alerts/scheduled reports, embedding, a Helm chart, a built-in MCP server, and an extension system — but its dashboards are grids of chart plugins, not AI-authored HTML. Metabase and Grafana have comparable governance but are AGPL with key features (RLS, SAML, serialization, reporting, fine-grained RBAC) paywalled; Lightdash (MIT core) has the most "TabFree-like" AI authoring (Claude Code-generated React "data apps" in a sandboxed iframe with proxied, permission-enforced queries) but that lives in its source-available Enterprise directory; Evidence and Rill are code-first but put governance in their commercial clouds.

### Inferences
- **Only Superset satisfies "permissive + server-grade governance + live Athena/Redshift + MCP" entirely in open source.** Redash is permissive (BSD-2) with Athena/Redshift and SAML/LDAP/Google auth but no RLS or MCP found; Lightdash's MIT core has Athena/Redshift and a scheduler but its AI/MCP/data-apps/SCIM/embedding live in the source-available `ee/` directory; Cube Core is permissive with access policies but is headless.
- **AGPL + paid-feature gating makes Metabase and Grafana poor fork bases for a permissive project**: forking would make TabFree AGPL and you would still have to rebuild the paywalled features (Metabase: RLS, SAML/OIDC, serialization, custom viz; Grafana: SAML, fine-grained RBAC, reporting). Kibana, Knowage, Helical Insight, RATH, Briefer and DAC are AGPL as well; DataEase/SQLBot's "modified GPLv3" adds logo-retention and relicensing clauses (arguably more restrictive than plain GPL); Chartbrew (FSL), Chat2DB (source-available), and Pentaho (BSL since 2026) are not OSI open source.
- **Rill conflicts with the "no extract engine" requirement**: Athena/Redshift are ingestion sources into DuckDB/ClickHouse etc., and governance (users, SSO, alerts, reports, embedding) is in the Rill Cloud SaaS.
- **Evidence is the cleanest AI-authorable format (Markdown + SQL) with live Athena/Redshift**, but OSS self-hosting has no per-user auth/RLS — TabFree would have to build the entire governance server around it.
- **Code-first frameworks (Streamlit, Dash, marimo, Quarto, Observable Framework, Vizro, Lumen, Datasette)** are good runtimes for AI-written dashboards but none ships a multi-tenant governed server (RBAC/RLS/subscriptions) in OSS; Observable Framework's activity has slowed (last release March 2026).
- **Count, Hex and Steep** are proprietary SaaS (not OSS) and cannot serve as a base (per the brief; not re-verified individually).
- **Abandoned/archived (avoid)**: Davinci, Datart, Poli, Dashbuilder, SQLPad, Briefer, Malloy Composer (stale), RATH (stale).
- **AWS story**: Superset has the strongest first-party K8s story (Helm chart in repo → EKS); Grafana has an AWS-managed option (Amazon Managed Grafana); Metabase documents Elastic Beanstalk + RDS; Lightdash publishes Helm charts; Evidence ships a Docker image; Rill is SaaS-only. No first-party Terraform modules for Superset/Metabase/Lightdash on AWS surfaced in a quick GitHub search.

## 2. Open-source AI/LLM dashboard, text-to-SQL and MCP-native BI projects — which generate full dashboards (multiple linked charts + filters)?

### Takeaway
Full multi-chart dashboards are generated by (a) MCP servers built into BI servers — Superset (`generate_chart` → `generate_dashboard` with layout), Metabase (MCP + paid CLI workflow), Grafana (`mcp-grafana` creates/patches dashboard JSON), Lightdash (Enterprise data apps/agents) — and (b) a few standalone tools: WrenAI (now Apache-2.0 core; deploys agent-built dashboards), DB-GPT (charts, dashboards, HTML reports), Vizro-MCP, Lumen AI, and Bruin's DAC. Most text-to-SQL tools (Vanna — archived, LIDA — inactive, Data Formulator, PandasAI, Chat2DB, SQLChat, DataLine, Dataherald — inactive, SQLBot) produce single answers/charts, not governed dashboards. MCP Apps (spec 2026-01-26) is now the standard for returning interactive HTML UI from MCP tools.

## 3. Which platforms have a Tableau migration path or Tableau import (even partial)?

### Takeaway
No open-source BI platform ships a native Tableau workbook importer. The only platform-adjacent path found is Preset's Apache-2.0 `tableau-to-preset` agent skill, which uses Superset's MCP tools to convert a `.twb/.twbx` dashboard into a Superset/Preset dashboard (chart-type mapping, calculated-field audit, filters, `position_json` layout). Several tools (DataEase, Graphic Walker) market themselves as "Tableau alternatives" but have no import.

### Cited Findings
- `tableau-to-preset` skill: "Guided workflow for converting a Tableau workbook (.twb or .twbx) to a Preset dashboard via Superset MCP tools"; parses TWB XML with Python's `xml.etree.ElementTree`; unzips `.twbx`; maps dashboard zones; classifies each field exact/substitute/proxy/dropped; one `generate_chart` per worksheet; carries translatable filters; calls `generate_dashboard` with `position_json` to reproduce layout; treats workbook strings as untrusted; extract-backed (`.hyper`/`.tde`) workbooks fall back to substitute datasets; probes `get_chart_type_schema` before degrading (maps, treemaps, Gantt) — [SKILL.md](https://github.com/preset-io/agent-skills/blob/HEAD/plugins/preset-mcp-skills/skills/tableau-to-preset/SKILL.md)
- The skills repo is Apache-2.0, created 2026-05-28, v0.5.0 (2026-10-05), described as "Agent skills for Preset, Apache Superset and Superset MCP" — [preset-io/agent-skills](https://github.com/preset-io/agent-skills)
- DataEase describes itself as "An open-source BI tool alternative to Tableau" — [repo](https://github.com/dataease/dataease); Graphic Walker as "a different open-source alternative to Tableau" — [repo](https://github.com/Kanaries/graphic-walker)
- The R package `twbparser` parses workbooks and offers a migration-readiness assessment with Superset among listed targets — [CRAN reference](https://cran.nics.utk.edu/cran/web/packages/twbparser/refman/twbparser.html)
- A consultancy sells Tableau→Superset migration services using proprietary mapping tools — [Andolasoft](https://andolasoft.com/what-we-do/tableau-migration-services)

### Inferences
- Superset is the only OSS target with a ready-made, AI-driven Tableau conversion workflow; TabFree could reuse the skill's approach (or the skill itself, Apache-2.0) if built on Superset, or adapt its parsing/mapping rules for TabFree's own HTML-dashboard target.
- A Tableau *Server* migration (users, groups, projects, permissions, schedules, subscriptions, data sources) is not covered by any OSS platform; only workbook-level conversion exists. (Converter repos and commercial tools are covered by the separate researcher.)

### Gaps
- No native Tableau import found in Metabase, Lightdash, Redash, Grafana, Evidence, Rill, DataEase, Knowage or Helical docs reviewed; a full-text search of every platform's issue tracker was not performed.
- Quality/coverage of the Preset skill on real-world workbooks is unknown.

## 4. If TabFree were built on one platform, which is best and why — and which are poor fits? (ranked recommendation)

### Takeaway
Recommendation: **extend Apache Superset rather than fork it or build everything new** — run TabFree as a Superset-based distribution where AI-authored HTML dashboards are a new, sandboxed content type (via Superset's `.supx` extension system) whose queries go through Superset's dataset/chart-data APIs so Superset's RBAC, RLS, guest tokens, alerts/reports, MCP server and Helm/EKS deployment are reused. If the team will not accept Superset's Python/Flask/Celery stack, the next-best path is to build a new thin governed server modeled on Lightdash's data-apps architecture, using permissive components (Cube Core or WrenAI core for semantics/access policies, MCP Apps for in-chat rendering). Metabase, Grafana, Rill, Evidence, DataEase and the AGPL/BSL/FSL projects are poor bases.

### Cited Findings
- Superset is Apache-2.0, ASF-governed, 75,586 stars, release 6.1.0 (2026-05-13) — [repo](https://github.com/apache/superset)
- Superset Extensions let organizations "build custom features without modifying the core codebase" with React frontend + Python backend in `.supx` packages — [overview.md](https://github.com/apache/superset/blob/HEAD/docs/developer_docs/extensions/overview.md)
- Superset MCP server runs with "Superset context (app, db, RBAC)" and can create charts/dashboards; it refuses mutations to "externally managed dashboards" — [mcp-server.mdx](https://github.com/apache/superset/blob/HEAD/docs/admin_docs/configuration/mcp-server.mdx), [using-ai](https://github.com/apache/superset/blob/HEAD/docs/docs/using-superset/using-ai-with-superset.mdx)
- Superset RLS with Role/Group subjects, `DASHBOARD_RBAC`, guest tokens for embedding — [security.mdx](https://github.com/apache/superset/blob/HEAD/docs/admin_docs/security/security.mdx)
- Superset Athena and Redshift docs — [athena](https://github.com/apache/superset/blob/HEAD/docs/user_docs_versioned_docs/version-6.1.0/databases/supported/amazon-athena.mdx), [redshift](https://github.com/apache/superset/blob/HEAD/docs/user_docs_versioned_docs/version-6.1.0/databases/supported/amazon-redshift.mdx); alerts/reports — [doc](https://github.com/apache/superset/blob/HEAD/docs/admin_docs/configuration/alerts-reports.mdx); Helm — [chart](https://github.com/apache/superset/tree/HEAD/helm/superset)
- Lightdash's reference design for AI-written apps: sandboxed iframe with no API access; host page proxies every query so permissions, user attributes and row-level filters are enforced; append-only versions; Claude Code/Codex in pluggable sandboxes (incl. AWS Lambda microVM) — [data-apps.md](https://github.com/lightdash/lightdash/blob/HEAD/docs/data-apps.md), [SandboxRuntime](https://github.com/lightdash/lightdash/tree/HEAD/packages/backend/src/ee/services/SandboxRuntime) — but it is "Enterprise-only" under the Lightdash Source Available License — [ee LICENSE](https://github.com/lightdash/lightdash/blob/HEAD/packages/backend/src/ee/LICENSE)
- Cube Core is Apache-2.0 (some MIT) with Athena/Redshift drivers and data access policies (row-level filters, member restrictions, masking) — [LICENSE](https://github.com/cube-js/cube/blob/HEAD/LICENSE), [policies](https://github.com/cube-js/cube/blob/HEAD/docs-mintlify/docs/data-modeling/access-policies-viewer.mdx)
- WrenAI core/SDK/skills are Apache-2.0 since May 2026 — [LICENSE](https://github.com/Canner/WrenAI/blob/HEAD/LICENSE)
- Metabase RLS/SAML/serialization/custom-viz/agent-driven development are paid; core is AGPL — [LICENSE](https://github.com/metabase/metabase/blob/HEAD/LICENSE.txt), [RLS](https://github.com/metabase/metabase/blob/HEAD/docs/permissions/row-and-column-security.md), [agent-driven dev](https://github.com/metabase/metabase/blob/HEAD/docs/ai/agent-driven-development.md)
- Grafana is AGPL-3.0; RBAC, SAML, reporting are Enterprise/Cloud — [repo](https://github.com/grafana/grafana), [RBAC](https://github.com/grafana/grafana/blob/HEAD/docs/sources/administration/roles-and-permissions/access-control/_index.md), [reports](https://github.com/grafana/grafana/blob/HEAD/docs/sources/visualizations/dashboards/create-reports/_index.md)
- Rill: Athena/Redshift ingest-only; Cloud is SaaS — [olap dir](https://github.com/rilldata/rill/tree/HEAD/docs/docs/developers/build/connectors/olap), [pricing](https://www.rilldata.com/pricing)
- Evidence self-host lacks user auth, access controls and agents — [self-host](https://github.com/evidence-dev/evidence/blob/HEAD/docs/self-host/index.mdx)

### Inferences
Ranked options (best first):
1. **Extend Superset (recommended).** Fit: permissive license compatible with an Apache-2.0/MIT TabFree; no open-core gates; live Athena/Redshift; RBAC + RLS + groups; alerts/reports; embedding/guest tokens; built-in, RBAC-aware MCP server to extend with "author HTML dashboard" tools; extension system to add an "HTML dashboard" content type (sandboxed iframe + postMessage query proxy through Superset's data API, mirroring Lightdash's and MCP Apps' patterns); Helm chart for EKS; Preset's Tableau-conversion skill as a migration starting point; large contributor base. Costs/risks: heavy Python/Flask + Celery + React stack; dashboards-as-code is export/import rather than Git-native; SAML needs custom work; extension API maturity and the evolving MCP surface (Superset 5.0+/6.x) must be validated; TabFree's HTML dashboards would be a parallel model to native Superset dashboards.
2. **Build new, compose permissive parts.** A thin TabFree server (auth/SSO, RBAC/RLS, scheduler, subscriptions, content store with Git versioning, MCP server with MCP Apps output) that runs AI-written HTML/JS dashboards in sandboxed iframes and proxies all queries to Athena/Redshift (directly or via Cube Core/WrenAI core for semantics and access policies); visual exploration from Graphic Walker (Apache-2.0) and pivot grids from Perspective (Apache-2.0). Best architectural fit for "AI writes HTML," highest effort (re-implementing Tableau Server-style governance that Superset already has).
3. **Fork Lightdash's MIT core.** Good modern TypeScript stack, Athena/Redshift clients, scheduler, dashboards-as-code, but requires a dbt/YAML semantic layer and the AI agent/MCP/data-apps/SCIM/embedding code is source-available Enterprise — a fork would have to re-create exactly the parts TabFree cares most about.
4. **Redash (BSD-2).** Permissive, Athena/Redshift, SAML/LDAP/Google, community-maintained releases into 2026 — but no RLS or MCP found and a simpler dashboard model; more to rebuild than Superset.
5. **Malloy Publisher (MIT) as an engine.** Design is closest to "agents author governed HTML data apps over a semantic model via MCP," but it is young (134 stars), relies on an external gateway for authentication, lists no Athena/Redshift connectors, and has no subscription/RBAC UI.
Poor fits: Metabase (AGPL + paid governance), Grafana (AGPL + Enterprise gating + observability focus), Kibana/OpenSearch Dashboards (search-engine-bound; Kibana AGPL/SSPL/ELv2), Rill (extract-based for Athena/Redshift; governance in SaaS), Evidence (governance only in Studio), DataEase/SQLBot (modified GPLv3), Knowage/Helical/RATH/Briefer/DAC (AGPL), Pentaho (BSL), Chartbrew (FSL), Chat2DB (source-available), app frameworks without a governed server (Streamlit, Dash, marimo, Quarto, Observable Framework, Vizro, Lumen), and abandoned projects (Davinci, Datart, Poli, Dashbuilder, SQLPad, LIDA, Dataherald, Vanna).

### Gaps
- No hands-on evaluation of Superset's extension API (stability, sandboxing primitives, ability to add a new dashboard type) was possible; this is the key technical risk to validate with a spike.
- Licensing statements here are not legal advice; AGPL/modified-GPL compatibility conclusions should be confirmed by counsel.
- Performance/scale of Superset with Athena (async queries, caching) vs a purpose-built server was not assessed.

## 6. Verdict: does any existing open-source platform already effectively "be" TabFree?

### Takeaway
No. Nothing open source today combines (1) AI-authored HTML dashboards via a built-in MCP server, (2) live Athena + Redshift without extracts, (3) Tableau-Server-grade RBAC/RLS/SSO/schedules/subscriptions, (4) a permissive license with no paid gates, and (5) Tableau content migration. The nearest equivalents are Lightdash Enterprise (closest function, but source-available/paid and dbt-centric), Apache Superset + its MCP server + Preset's Tableau skill (closest open-source server, but chart-grid dashboards rather than HTML), and Malloy Publisher (closest open design for governed HTML data apps, but immature).

### Cited Findings
- Lightdash data apps are "Enterprise-only" and require a paid add-on on Cloud Pro/Enterprise — [data-apps.md](https://github.com/lightdash/lightdash/blob/HEAD/docs/data-apps.md), [docs](https://docs.lightdash.com/data-apps)
- Superset's AI features create charts/dashboards through MCP (not HTML pages) and it is Apache-2.0 — [using-ai](https://github.com/apache/superset/blob/HEAD/docs/docs/using-superset/using-ai-with-superset.mdx), [repo](https://github.com/apache/superset)
- Preset's `tableau-to-preset` skill provides workbook-level conversion via Superset MCP — [SKILL.md](https://github.com/preset-io/agent-skills/blob/HEAD/plugins/preset-mcp-skills/skills/tableau-to-preset/SKILL.md)
- Malloy Publisher ships HTML data apps with access filters, but relies on an external gateway for auth and has 134 stars — [README](https://github.com/malloydata/publisher)
- Evidence self-host lacks user auth/access control; Rill's governance is in Rill Cloud; Metabase/Grafana gate RLS/SAML/reporting behind paid editions — [Evidence](https://github.com/evidence-dev/evidence/blob/HEAD/docs/self-host/index.mdx), [Rill pricing](https://www.rilldata.com/pricing), [Metabase RLS](https://github.com/metabase/metabase/blob/HEAD/docs/permissions/row-and-column-security.md), [Grafana RBAC](https://github.com/grafana/grafana/blob/HEAD/docs/sources/administration/roles-and-permissions/access-control/_index.md)

### Inferences
- TabFree is a genuine gap in the open-source landscape, but not a greenfield one: the governance half exists in Superset (permissive), the AI-HTML-authoring half is proven in Lightdash EE (proprietary) and MCP Apps (open standard). The lowest-risk path is "Superset as the governed backbone + a TabFree HTML-dashboard extension + extended MCP tools + a Tableau Server migrator," with a build-new fallback if a spike shows Superset's extension system cannot host sandboxed HTML dashboards cleanly.

### Gaps
- Commercial equivalents (e.g., hosted Lightdash/Evidence/Preset offerings vs Tableau Cloud pricing) and Tableau-specific converters are out of scope here and covered by the other researcher.
