# Every Piece Exists, Nobody Assembled TabFree

**No open-source project or commercial product does what TabFree proposes as of 20 November 2026, although every component exists somewhere, usually bolted to a proprietary destination.** Tableau itself now lets Claude, ChatGPT or Codex write HTML/JS "Data Apps" through its MCP server under Tableau permissions, but only inside paid Tableau and in beta ([Salesforce](https://www.salesforce.com/blog/tableau-data-apps-from-prompt-to-trusted-agentic-analytics/)). Lightdash ships the right runtime design, with Claude Code–generated React apps running in a sandboxed iframe whose every query is proxied and permission-checked, but only in its source-available Enterprise tier ([Lightdash](https://github.com/lightdash/lightdash/blob/HEAD/docs/data-apps.md)). Apache Superset is the only permissively licensed server with Athena, Redshift, RBAC, row-level security, alerts and a built-in MCP server, yet its dashboards are chart grids rather than AI-authored pages ([Superset](https://github.com/apache/superset/blob/HEAD/docs/admin_docs/configuration/mcp-server.mdx)), and the closest open migration tool, the month-old unshackle, turns a Tableau Server into notebooks and Cedar policy files that it explicitly does not enforce ([unshackle](https://github.com/Querio-App/unshackle)). The real gap is a vendor-neutral, self-hosted destination with Tableau-Server-grade governance, .hyper-to-Iceberg conversion, Athena-native queries and dashboards as reviewable code that Claude edits through MCP. The team starts well ahead of zero, because Tableau has published Apache-2.0 schemas for the workbook format, a grammar for its calculation language, an MCP server that downloads workbooks and renders views, and a Hyper API that exports extracts to Parquet. What nobody has built, and what will decide success, is a compiler that reproduces Tableau's query semantics on Athena and Redshift plus an engine that reproduces Tableau's effective permissions: one open converter's self-test on Tableau's own Superstore sample translated just **23.5% of calculations and 34.4% of worksheets** ([tab2pbi](https://github.com/AyushSingh110/Tableau-to-Power-BI-semantic-compiler)). This report recommends a thin new governed core rather than extending Superset (subject to a short spike), a governed JSON dashboard spec with sandboxed HTML escape hatches, Cube Core plus a TabFree-owned Tableau-semantics compiler, Iceberg tables queried by Athena behind a mandatory cache, and a new product name, because Salesforce's trademark rules forbid "any recognizable portion" or abbreviation of Tableau in a product name ([Salesforce](https://www.salesforce.com/company/legal/tmcusageguidelines/)).

## No product or repository meets all seven TabFree requirements

The brief has seven parts: a free, open-source server on AWS; web dashboards authored by Claude Code instead of a desktop app; conversion of .twb/.twbx, .tds/.tdsx and .hyper/.tde files to open formats; extract data stored in and queried from Athena or Redshift; migration and recreation of every dashboard and data source on an existing Tableau Server; user edits through a built-in Claude Code and MCP integration; and Tableau-grade permissions and server features. **Nothing found satisfies more than two or three at once.** This research swept GitHub (173 repository and topic searches plus 24 code searches), the full PyPI index, npm, GitLab and the commercial migration market. Searches for an open Tableau Server alternative return zero repositories ([GitHub search](https://github.com/search?q=tableau+server+alternative&type=repositories)), as do searches for Tableau-extract-to-Athena and Tableau-to-HTML converters ([GitHub search](https://github.com/search?q=tableau+extract+athena&type=repositories)). On the commercial side, **every converter targets another proprietary BI product**: Power BI/Fabric, Amazon Quick Sight, Looker, Sigma, Databricks AI/BI, Preset or Snowflake Streamlit. Automation claims range from 60–80% ([SquareShift](https://www.squareshift.co/post/tableau-to-looker-migration-accelerator)) to "often 95–98%" ([DataKulture](https://datakulture.com/blog/tableau-to-power%20bi-migration/)), all self-reported and none independently benchmarked. Two TabFree goals are nearly absent from that market. No commercial tool converts .hyper extracts into open formats, and only Pulse Convert, a Power BI converter, even claims to move "access roles, refresh schedules, and dataset permissions" ([Office Solution](https://innovationalofficesolution.com/Tableau-To-PowerBI/)). No converter targets Athena: AWS's own Transform agents, built by Wavicle before Deloitte bought its assets on 31 August 2026, rebuild Tableau content inside Amazon Quick Sight ([Amazon Quick Community](https://community.amazonquick.com/t/aws-transform-now-offers-bi-migration-agents-for-power-bi-and-tableau-to-amazon-quick/52292)) ([Deloitte](https://www.deloitte.com/us/en/about/press-room/deloitte-aquires-the-business-of-wavicle-a-top-tier-data-and-ai-engineering-organization.html)).

**The closest conceptual match is Tableau's own November 2026 stack.** A Tableau Data App is "a custom, interactive analytical web app hosted and powered by the Tableau platform": any MCP-compliant agent such as Claude Desktop, ChatGPT or Codex builds it through the Tableau MCP server, it is packaged inside a .twbx, and it inherits Tableau permissions and row-level security without ever seeing database credentials ([Salesforce](https://www.salesforce.com/blog/tableau-data-apps-from-prompt-to-trusted-agentic-analytics/)). Tableau's plugin was tested with real React and d3 bundles ([tableau-plugin PR #13](https://github.com/tableau/tableau-plugin/pull/13)), its MCP server gained Desktop authoring tools in the 2026.3.1 release ([Tableau MCP docs](https://tableau.github.io/tableau-mcp/docs/intro)), and Tableau Studio puts an agent inside Desktop ([Ladataviz](https://newsletter.ladataviz.com/p/the-end-of-tableau-desktop)). All of it is gated. Studio's agentic features need a Creator license on Tableau+, Cloud+ or Server+ ([Tableau Studio](https://www.tableau.com/products/tableau-studio)), and the Data Apps developer docs require a Tableau Cloud site that supports data apps ([Data Apps docs](https://tableau.github.io/extensions-api/docs/dataapps/trex_dataapp_getstarted/)); whether Data Apps run on Tableau Server today is unresolved because sources conflict ([datastudios](https://www.datastudios.org/post/tableau-data-apps-beta-claude-chatgpt-mcp-governed-analytics-apps)). Tableau has validated TabFree's authoring thesis and then locked it to its own stack. That narrows TabFree's differentiation to what Tableau will not offer: no license fees, self-hosting on AWS, open data formats and Athena/Redshift-native queries.

Among open-source platforms, **Apache Superset is the only permissively licensed server with the governance half.** It is Apache-2.0 under ASF governance with 75,586 stars, documents Athena and Redshift connections, ships built-in roles, row-level security rules with role and group subjects, guest-token embedding, scheduled reports, SQL-condition alerts and a Helm chart, and since version 5.0 includes an MCP server that creates charts and dashboards inside Superset's RBAC context ([Superset repo](https://github.com/apache/superset)) ([Superset security](https://github.com/apache/superset/blob/HEAD/docs/admin_docs/security/security.mdx)) ([Superset MCP](https://github.com/apache/superset/blob/HEAD/docs/admin_docs/configuration/mcp-server.mdx)). **Lightdash has the authoring half.** Its data apps are "AI-generated interactive React applications" written by "Claude Code or Codex", versioned append-only, and run "in a sandboxed iframe with no API access" while the host page proxies every query so that permissions and row-level filters "are enforced by Lightdash, never by the app" ([Lightdash architecture](https://github.com/lightdash/lightdash/blob/HEAD/docs/data-apps.md)); the feature is Enterprise-only under the Lightdash Source Available License ([Lightdash ee license](https://github.com/lightdash/lightdash/blob/HEAD/packages/backend/src/ee/LICENSE)). The rest fall short structurally. Metabase and Grafana are AGPL with row-level security, SAML and reporting behind paid editions ([Metabase RLS](https://github.com/metabase/metabase/blob/HEAD/docs/permissions/row-and-column-security.md)) ([Grafana RBAC](https://github.com/grafana/grafana/blob/HEAD/docs/sources/administration/roles-and-permissions/access-control/_index.md)). Evidence's self-hosted build has no per-user authentication or access control ([Evidence self-host](https://github.com/evidence-dev/evidence/blob/HEAD/docs/self-host/index.mdx)). Rill treats Athena and Redshift only as ingestion sources ([Rill connectors](https://github.com/rilldata/rill/tree/HEAD/docs/docs/developers/build/connectors/olap)). Malloy Publisher, the cleanest open design for governed "no-build HTML data apps", has 134 stars, depends on an external gateway for authentication and lists no Athena or Redshift connector ([Malloy Publisher](https://github.com/malloydata/publisher)). None imports Tableau workbooks natively; the only platform-adjacent path is Preset's Apache-2.0 tableau-to-preset agent skill, which converts one workbook at a time through Superset's MCP tools ([Preset skill](https://github.com/preset-io/agent-skills/blob/HEAD/plugins/preset-mcp-skills/skills/tableau-to-preset/SKILL.md)).

On the migration side, **the only open project aimed at open formats is unshackle**: Apache-2.0, created 22 October 2026, at v0.3.0 by 19 November with 338 commits and 11 stars. It signs in to Tableau Server or Cloud with a personal access token, inventories and downloads content, maps calculated fields and FIXED LODs to Apache Ossie metrics, dashboards to Jupyter notebooks, group permissions to Cedar policies and USERNAME()/ISMEMBEROF() user filters to SQL row filters, copies .hyper data through the Hyper API, and checks numbers against Tableau's saved view data ([unshackle Tableau doc](https://github.com/Querio-App/unshackle/blob/main/docs/tools/tableau.md)). It leaves table calculations, INCLUDE/EXCLUDE LODs, multi-dimension FIXED LODs, custom SQL and project default permissions as TODO, produces notebooks rather than hosted dashboards, loads nothing into Athena or Redshift, and says plainly that "policies are agent context and are not enforced" ([unshackle README](https://github.com/Querio-App/unshackle)). The strongest commercial converter to *code* is Snowflake's Cortex Code skill, which turns a workbook into a multipage Streamlit app and translates LODs, table calculations, sets, parameters and filter and highlight actions; it runs only on Snowflake, does not read .hyper extracts, ignores server objects, and blocks SCRIPT_*, MODEL_* and PREVIOUS_VALUE until a human translates them ([Snowflake docs](https://docs.snowflake.com/developer-guide/streamlit/migrations-and-upgrades/tableau-to-streamlit)). Databricks made bulk Genie Code conversion generally available on 19 November 2026 ([Databricks](https://www.databricks.com/blog/bulk-migrate-your-dashboards-aibi-genie-code)) and Sigma publishes its converter as an open-source Claude Code plugin with parity checks ([Sigma](https://www.sigmacomputing.com/product/migrations)), but both land content in their own platforms. Three forces shape the opening. **Anthropic's Claude Data**, generally available since 10 November 2026, already lets Claude build live dashboards on Amazon Redshift with certified queries and live sharing, though as a claude.ai feature with no Tableau migration path ([Claude](https://claude.com/resources/articles/sheets-whiteboards-data)). Platform vendors subsidize exits: AWS points Tableau customers to "free or discounted" migration programs into Quick Sight ([Amazon Quick Community](https://community.amazonquick.com/t/aws-transform-now-offers-bi-migration-agents-for-power-bi-and-tableau-to-amazon-quick/52292)), whose dashboard authoring requires the Enterprise tier at $40 per user plus $250 per account each month ([AWS Quick pricing](https://aws.amazon.com/quick/pricing/)). And **no deadline forces anyone to move**: Tableau Server returns to four-month major releases from 2026.3, with no end-of-life announcement ([Tableau blog](https://www.tableau.com/blog/tableau-updates-product-release-cadence)). Demand will therefore rest on cost and AI gaps, which are real but unquantified. Salesforce's CFO cited "increased softness in Tableau bookings and renewals" in May 2026 ([CIO Dive](https://ciodive.com/news/salesforce-agentforce-earnings-saaspocalypse/821413/)), reported list prices run $75–115 per Creator and $15–35 per Viewer per month ([datastudios](https://www.datastudios.org/post/tableau-pricing-creator-explorer-viewer-standard-enterprise-tableau-plus)), and new features reach Cloud one to three quarters before Server ([Thinklytics](https://thinklytics.com/insights/tableau-cloud-migration-2026)), yet no independent churn survey or market-size estimate exists. Because "Claude Code plus skills plus MCP" is already how Sigma, Preset, Snowflake, Databricks and Tableau approach Tableau conversion, **TabFree's novelty is its destination, not its migration technique**.

## Tableau's own Apache-2.0 releases are the biggest reuse win

The most valuable reusable assets come from Tableau, and most appeared in 2025–2026 under permissive licenses. **Official workbook schemas** (Apache-2.0, formally published February 2026) define element order and enumerations for TWB versions 2026.1 through 2026.3. They check syntax only: connection attributes, calculation contents and cross-references sit in `processContents="skip"` regions (18 of them in the 2026.3 schema), and packaged .twbx files are out of scope ([tableau-document-schemas](https://github.com/tableau/tableau-document-schemas)) ([2026.3 XSD](https://github.com/tableau/tableau-document-schemas/blob/main/schemas/2026_3/twb_2026.3.0.xsd)). **An official ANTLR4 grammar for the calculation language**, 212 lines including `LODSCOPE: FIXED | INCLUDE | EXCLUDE`, ships under Apache-2.0 inside an AI-evaluation repository rather than as a package, so TabFree should vendor it with attribution and track upstream changes ([TableauCalculationGrammar.g4](https://github.com/tableau/Tableau-AI-Model-Evaluation-Tool/blob/main/packages/evals/src/validator/grammar/TableauCalculationGrammar.g4)) ([CALC_GRAMMAR.md](https://github.com/tableau/Tableau-AI-Model-Evaluation-Tool/blob/main/docs/CALC_GRAMMAR.md)). **The official MCP server** (Apache-2.0, v6.0.4) exposes 55 web tools, among them `download-workbook`, `get-view-data`, `get-view-image`, `query-datasource` and `query-admin-insights`; it can be self-hosted against Tableau Server with a personal access token and ships a separate Desktop authoring server of about 78 tools ([toolName.ts](https://github.com/tableau/tableau-mcp/blob/main/src/tools/web/toolName.ts)) ([tableau-mcp](https://github.com/tableau/tableau-mcp)). Tableau's connector SDK holds the two most underrated assets, both MIT-licensed: **about 860 TDVT expression-test files that pair Tableau formulas with expected results**, and a FullFunctionMap dialect template with 305 function entries showing how Tableau itself maps its functions to SQL ([TDVT exprtests](https://github.com/tableau/connector-plugin-sdk/tree/master/tdvt/tdvt/exprtests/standard)) ([FullFunctionMap.tdd](https://github.com/tableau/connector-plugin-sdk/blob/master/samples/components/dialects/FullFunctionMap.tdd)).

For data and operations, **the Hyper API has been Apache-2.0 since release 0.0.19691 in July 2024** ([Hyper releases](https://tableau.github.io/hyper-db/docs/releases)), and Hyper's archived SQL reference documents `COPY … TO` writing Parquet straight to S3 ([COPY TO](https://github.com/tableau/hyper-db/blob/0fb9fa323c5236c490c59a96a3b57f0583381cf6/website/docs/sql/command/copy_to.md)); pantab (BSD-3) and an official pure-Rust client, which still needs the `hyperd` binary, are alternative front ends ([pantab](https://github.com/innobi/pantab)) ([hyper-api-rust](https://github.com/tableau/hyper-api-rust)). The VizQL Data Service queries published data sources on Server 2025.1 and later and has an Apache-2.0 Python SDK, which makes it a calculation oracle for parity tests ([VDS](https://help.tableau.com/current/api/vizql-data-service/en-us/index.html)) ([VizQL-Data-Service](https://github.com/tableau/VizQL-Data-Service)). The Tableau Server Client library (MIT, v0.42) covers permissions, default permissions, schedules, subscriptions and custom views ([TSC](https://github.com/tableau/server-client-python)). The Apache-2.0 Migration SDK always publishes into Tableau, but its crawl order, resumable manifest and hook-and-transformer design are worth copying ([tableau-migration-sdk](https://github.com/tableau/tableau-migration-sdk)). The repository data dictionary documents the `workgroup` PostgreSQL tables that hold what REST cannot return, though its repo carries no license file ([tableau-data-dictionary](https://github.com/tableau/tableau-data-dictionary)), and the archived VizAlerts project is Tableau's own open implementation of data-driven alerts ([VizAlerts](https://github.com/tableau/VizAlerts)).

Beyond Tableau's repositories, **unshackle is the one community project worth forking**; most other Tableau-specific code is young, single-maintainer and aimed at Power BI, so it belongs on the reference shelf rather than in the dependency tree. tableau_aid transpiles calculations to Presto SQL, Athena's dialect family, through a Lark grammar but leaves LODs as placeholders ([tableau_aid](https://github.com/TheRealHrishav/tableau_aid)); scapeTableau rewrites FIXED, INCLUDE and EXCLUDE into window functions or grain subqueries ([scapeTableau](https://github.com/lukashalim/scapeTableau)); Preset's skill classifies every field as exact, substitute, proxy or dropped and rebuilds layout from dashboard zones ([Preset skill](https://github.com/preset-io/agent-skills/blob/HEAD/plugins/preset-mcp-skills/skills/tableau-to-preset/SKILL.md)); and Sigma's `tableau-vds-to-cdw` lands VizQL Data Service results in a warehouse, a pattern that ports directly to Athena or Redshift ([sigma-migration-skills](https://github.com/sigmacomputing/sigma-migration-skills)). License hygiene matters. cwtwb is AGPL-3.0 ([cwtwb](https://github.com/aidatacooper/cwtwb)), the most extensive open Power BI generator has no license file ([cyphou](https://github.com/cyphou/TableauToPowerBI)), and ThoughtSpot's 130-plus-row coverage matrix, otherwise an excellent checklist of Tableau constructs, carries a non-standard license that needs review before reuse ([coverage matrix](https://github.com/thoughtspot/thoughtspot-agent-skills/blob/main/agents/cli/ts-convert-from-tableau/references/coverage-matrix.md)).

The runtime can be assembled from permissive parts: Cube Core (Apache-2.0) for semantics, pre-aggregation and row-level policies ([Cube](https://github.com/cube-js/cube)); OpenFGA or Cedar (both Apache-2.0 CNCF projects) for authorization ([OpenFGA](https://github.com/openfga/openfga)) ([Cedar](https://github.com/cedar-policy/cedar)); Vega-Lite (BSD-3), ECharts (Apache-2.0) and Perspective (Apache-2.0) for charts and pivots ([Vega-Lite](https://github.com/vega/vega-lite)) ([ECharts](https://github.com/apache/echarts)) ([Perspective](https://github.com/perspective-dev/perspective)); Graphic Walker (Apache-2.0) as a drag-and-drop explorer for Explorer-role users who rely on web edit today ([Graphic Walker](https://github.com/Kanaries/graphic-walker)); Playwright (Apache-2.0) for PDF and image snapshots ([Playwright](https://github.com/microsoft/playwright)); and the MCP Apps extension, moving to Apache-2.0, for rendering dashboards inside Claude and other MCP clients ([ext-apps](https://github.com/modelcontextprotocol/ext-apps)). What exists nowhere is the integration core: a compiler from worksheets to web charts; a calculation compiler that handles INCLUDE/EXCLUDE LODs and table-calc addressing for Trino and Redshift; a migrator for schedules, subscriptions, alerts, custom views and favorites; a runtime that enforces migrated permissions and row-level security; a pipeline that lands extracts in Athena or Redshift; and an independent .hyper reader. The only "DuckDB extension for Tableau's Hyper file type" is an unmodified extension template ([duckdb_hyper](https://github.com/Coco-Alemana/duckdb_hyper)), so every extract must pass through Tableau's engine at least once.

## Day one requires Tableau's permission contract and query semantics, not its authoring UI

Because the source is Tableau Server, priority means what existing workbooks and users depend on, not what Tableau can do, and that excludes three groups. Retired features need no runtime: Ask Data and its lenses and legacy Metrics (Cloud February 2024, Server 2024.2), Data Stories (2025.1) and View Acceleration (Server 2026.2), although the migrator should detect and report their leftovers ([Ask Data lens API](https://help.tableau.com/release-preview/api/rest_api/en-us/REST/rest_api_ref_ask_data_lens.htm)) ([Metrics](https://help.tableau.com/current/online/en-us/metrics_create.htm)) ([Data Stories](https://help.tableau.com/current/pro/desktop/en-us/data_stories.htm)) ([View Acceleration](https://help.tableau.com/current/server/en-us/data_acceleration.htm)). Cloud-only features such as Pulse, Bridge, Admin Insights and the Activity Log cannot exist in a Server estate ([Pulse](https://help.tableau.com/current/online/en-us/pulse_intro.htm)). Authoring UI—web edit, Personal Space, Tableau Agent—is replaced by Claude, but the *runtime semantics* of everything authors built must be reproduced, which is why blending and quick table calculations rank P0 even though nobody will author them in TabFree. | Interactivity | Filter and highlight actions, including legend highlighting; sorting; drill up and down | Set and parameter actions; dynamic zone visibility; show/hide and navigation buttons; viz in tooltip; URL actions | Pages playback; dashboard extensions |
| Distribution | Email subscriptions (PNG/PDF, scheduled or on refresh); PDF, image and crosstab exports | Conditional subscriptions; data-driven alerts; custom views; view underlying data | Comments; PowerPoint export; mobile app; Slack and Teams |
| Operations and APIs | Backup and restore, high availability, audit log; REST, Metadata and Hyper APIs as migration tooling | Admin usage views; revision history; embedding through connected-app-style tokens (P0 where portals embed) | Webhooks; JS API v1/v2 shim; Activity Log, Admin Insights and Pulse (Cloud-only) |
| Retired in Tableau | None | None | Ask Data and lenses, legacy Metrics, Data Stories, View Acceleration: skip, but detect leftovers |

The best usage evidence is Tableau Research's census of **25,620 multi-chart Tableau Public dashboards**: bar charts appear in 60%, line charts and maps in 25% each, tables in 24%, and bespoke Sankey or waterfall charts in under 0.5%; three-quarters are interactive, with filter controls in 69% of interactive dashboards, chart-to-chart actions in 46% and legend highlighting in 43% ([Purich et al.](https://arxiv.org/pdf/2306.16513)). Public dashboards skew toward designed storytelling, so enterprise estates almost certainly carry more crosstabs, exports, published data sources and row-level security; that assumption is unverified but operationally safe, which is why exports, subscriptions and RLS sit at P0 on operational rather than census grounds. Migration effort follows different variables. Sheet and calculated-field counts "correlate weakly with effort", while sets, set actions and chained dashboard actions form the hardest category, and a single set action can outweigh "forty plain calculated fields" ([Antares](https://getantares.io/tableau-dashboard-complexity-analysis/)). No public dataset gives LOD, table-calc or blending frequencies for enterprise workbooks, so **the first engineering deliverable should be a census of the team's own estate**: parse every .twb, count each construct, weight the counts by 90-day view traffic, and retire unused content before converting anything.

**Permissions are a P0 contract that must be translated as effective permissions, not copied rule by rule.** Tableau evaluates Allowed, Denied and Unspecified capability rules for users and groups ([Permissions](https://help.tableau.com/current/server/en-us/permissions.htm)), applies project default permissions and locked projects ([Project permissions](https://help.tableau.com/current/server/en-us/permissions_projects.htm)), caps everything by site role ([Site roles](https://help.tableau.com/current/server/en-us/users_site_roles.htm)), and gives views their own permissions when a workbook's tabs are hidden or its project is locked ([Permission capabilities](https://help.tableau.com/current/server/en-us/permissions_capabilities.htm)). The REST API returns only explicit grants; implicit owner and administrator rights are not listed, so TabFree must compute effective access itself ([REST permissions concepts](https://help.tableau.com/current/api/rest_api/en-us/REST/rest_api_concepts_permissions.htm)). Sources summarize Tableau's rule as "deny wins", but whether an explicit user-level Allow overrides a group-level Deny must be confirmed against Tableau's documentation before the model is frozen, because the two readings grant different access to the same person.

**User-generated state is the silent failure mode.** Subscriptions, custom views, favorites, data-driven alerts and comments belong to users, not workbooks, so a migration that renders every dashboard correctly can still feel like data loss. Tableau's own Migration SDK does not migrate comments, data-driven alerts, revisions, user filters, virtual connections or usage history ([Migration SDK planning](https://help.tableau.com/current/api/migration_sdk/en-us/docs/planning.html)), and the REST API has hard gaps: reading a data-driven alert omits its condition and threshold ([Notifications methods](https://help.tableau.com/current/api/rest_api/en-us/REST/rest_api_ref_notifications.htm)), comments have no endpoint, and embedded credentials can be exported only as an encrypted keychain that a linked Tableau destination can open ([Workbooks and views methods](https://help.tableau.com/current/api/rest_api/en-us/REST/rest_api_ref_workbooks_and_views.htm)). The Server repository fills most of these gaps. Read-only access to the `workgroup` PostgreSQL database on port 8060 exposes alert specifications (stored as an undocumented "platform-parsable blob"), comments, subscriptions to custom views, virtual-connection policy JSON and full usage history ([data dictionary](https://tableau.github.io/tableau-data-dictionary/2026.3/data_dictionary.htm)) ([repository access](https://help.tableau.com/current/server/en-us/perf_collect_server_repo.htm)). Repository access should therefore be a recommended crawler input, alerts whose conditions cannot be decoded should migrate pre-filled for owners to confirm, and database credentials should be re-provisioned natively through IAM roles and Secrets Manager. The Metadata API, the fastest route to calculation and lineage inventory, is free on Server but disabled by default, backfills slowly on large estates and caps queries at 20,000 nodes and 20 seconds by default, so it should be enabled well before the migration window ([Metadata API](https://help.tableau.com/current/api/metadata_api/en-us/docs/meta_api_start.html)) ([TSM options](https://help.tableau.com/current/server/en-us/cli_configuration-set_tsm.htm)).

The crawler should follow Tableau's own dependency order—users, groups, group sets, projects, data sources, flows, workbooks, extract refresh tasks, custom views, subscriptions, flow tasks, favorites ([ServerToCloudMigrationPipeline.cs](https://github.com/tableau/tableau-migration-sdk/blob/main/src/Tableau.Migration/Engine/Pipelines/ServerToCloudMigrationPipeline.cs))—key every object by server, site, LUID and revision so reruns are idempotent, and authenticate with a connected-app JWT, because personal access tokens do not allow concurrent sessions ([REST auth concepts](https://help.tableau.com/current/api/rest_api/en-us/REST/rest_api_concepts_auth.htm)). Two details trip naive crawlers: hidden worksheets have no view LUID and therefore no REST image or data export ([Metadata API Sheet](https://help.tableau.com/current/api/metadata_api/en-us/reference/sheet.doc.html)), and Query View Data returns summary data only, and only the first view's data when called on a dashboard ([Workbooks and views methods](https://help.tableau.com/current/api/rest_api/en-us/REST/rest_api_ref_workbooks_and_views.htm)).

## Semantics, not XML parsing, decides whether migrated numbers match

Parsing is the easy part. A .twb is plain XML with an official schema, and the field-to-column map, relationships, calculations, shelves, extract recipe and dashboard zone tree are all present in it ([2026.3 XSD](https://github.com/tableau/tableau-document-schemas/blob/main/schemas/2026_3/twb_2026.3.0.xsd)). The traps are mechanical. Real files use feature-flag element names such as `_.fcp.ObjectModelEncapsulateLegacy.true...object-graph` that appear nowhere in the schema ([Superstore Data App.twb](https://github.com/tableau/extensions-api/blob/main/Samples/DataApp/Tableau%20Superstore%20Data%20App/Tableau%20Superstore%20Data%20App.twb)); files saved by every release from 2019.1 to 2025.2 still declare `version='18.1'`, so version handling must key on the `source-build` attribute ([hr.twb](https://github.com/shreyamalogi/Predictive-HR-Intelligence-Analytics/blob/main/hr.twb)); and Tableau's own loader strips some sections on load ([tableau-mcp table-calc example](https://github.com/tableau/tableau-mcp/blob/main/src/desktop/data/examples/table-calc.json)). Normalizing flag names and keeping a lossless raw-XML passthrough for unrecognized elements prevents silent loss.

**The hard part is reproducing VizQL's query semantics, which Tableau documents only partially.** Filters run in a fixed order: extract filters, data source filters, context filters, then sets, Top N and FIXED LODs, then dimension filters, then INCLUDE/EXCLUDE LODs and blending, then measure filters, then table calculations and totals, then table-calculation filters ([OSU order of operations](https://it.osu.edu/data/tableau/tableau-order-of-operations)). Because FIXED expressions "are computed before dimension filters are applied" ([Tableau order of operations](https://help.tableau.com/current/pro/desktop/en-us/order_of_operations.htm)), the same formula returns different numbers once a filter is promoted to context, and Tableau publishes no join plans for LODs. A faithful compiler therefore needs staged CTEs (rows after context filters, rows after dimension filters, view aggregates, windowed results) with null-safe joins, verified empirically against Server output. Table calculations are computed "on the local data in Tableau" over the aggregated view, partitioned and addressed by the view's dimensions ([Table calculations](https://help.tableau.com/current/pro/desktop/en-us/calculations_tablecalculations.htm)). SQL window functions reproduce the static cases, but densification, `PREVIOUS_VALUE`, `TOTAL` over non-additive measures and "restarting every" need a client-side engine whose undocumented defaults must be learned from Tableau's own outputs. Relationships add their own planning—only relevant tables are queried, each at its native level of detail, with inner joins for dimension-only views and left joins plus extra queries to keep unmatched measures ([Relationships](https://help.tableau.com/current/pro/desktop/en-us/datasource_multitable_analysis_overview.htm))—and blends aggregate the secondary source before joining it ([Blending](https://help.tableau.com/current/pro/desktop/en-us/multiple_connections.htm)).

Even row-level formulas hide traps that textual translation misses. Tableau's `/` always returns a float and yields NULL on a zero divisor ([FullFunctionMap.tdd](https://github.com/tableau/connector-plugin-sdk/blob/master/samples/components/dialects/FullFunctionMap.tdd)); `INT` truncates toward zero ([Type conversion](https://help.tableau.com/current/pro/desktop/en-us/functions_functions_typeconversion.htm)); `IIF` returns NULL on an unknown test while `IF` routes it to `ELSE` ([Logical functions](https://help.tableau.com/current/pro/desktop/en-us/functions_functions_logical.htm)); week starts come from the data source and `DATEDIFF` counts boundaries ([Date functions](https://help.tableau.com/current/pro/desktop/en-us/functions_functions_date.htm)), whereas Trino truncates weeks to Monday and its `date_diff` measures elapsed units ([Trino date functions](https://trino.io/docs/current/functions/datetime.html)). User functions are a security trap as well as a semantic one: `USERNAME()` must compile to a bind parameter taken from the viewer's session, never to the engine's `current_user`, which on AWS is an IAM principal. Running TDVT's roughly 860 expression tests against Athena and Redshift copies of Tableau's test tables turns each of these traps into a measurable per-function pass rate.

Visual mapping is tractable but incomplete. Vega-Lite descends from the same Polaris table algebra VizQL uses ([Polaris](https://datavis.cs.columbia.edu/files/papers/polaris.pdf)), so marks, faceting, layered dual axes with independent scales and window transforms map cleanly; ECharts covers treemaps, geographic maps and large mark counts; nested crosstabs with subtotals are better rendered as HTML grids. Tableau's "Automatic" mark choice is undocumented, its built-in geocoding must be replaced with open boundary data, and no TWB-to-Vega-Lite converter exists anywhere ([GitHub search](https://github.com/search?q=tableau+to+vega-lite&type=repositories)).

**Full automation is not a realistic target, and the vendors most candid about it say so.** Snowflake warns that a compiled query "doesn't prove its results match the workbook" ([Snowflake docs](https://docs.snowflake.com/developer-guide/streamlit/migrations-and-upgrades/tableau-to-streamlit)), Databricks says "Completed" does not mean every visual is final ([Databricks docs](https://docs.databricks.com/aws/en/dashboards/manage/import-bi)), and even a vendor selling conversion at $200 per dashboard concedes that "no cross-platform conversion delivers pixel-perfect reproduction" ([Antares](https://getantares.io/best-tableau-to-power-bi-migration-tool/)). Open converters confirm it: besides the Superstore self-test cited above, the most extensive open Power BI generator reports its own corpus gate as "FAILED: 30/44" ([cyphou](https://github.com/cyphou/TableauToPowerBI)). The credible 2026 pipelines pair agent-driven conversion with explicit parity gates—Sigma marks results green only when numbers and visuals match ([Sigma](https://www.sigmacomputing.com/product/migrations)), the Hex skill loops on screenshot diffs ([tableau-to-hex-skill](https://github.com/Humphrey4data/tableau-to-hex-skill)), unshackle verifies against Tableau's view data—and the more rigorous open converters put a deterministic intermediate representation underneath that refuses or flags what it cannot translate ([t2pbi-studio](https://github.com/nomie7/t2pbi-studio)). That design depends on **ground truth that exists only while Tableau Server is running**: per-view PNGs, PDFs, summary CSVs and crosstabs captured under `vf_` filter and parameter permutations ([REST filtering](https://help.tableau.com/current/api/rest_api/en-us/REST/rest_api_concepts_filtering_and_sorting.htm)); calculation results from the VizQL Data Service, which is rate-limited to 100 queries per hour per Creator license and excludes fiscal dates, RAWSQL, sets and spatial calculations ([VDS limitations](https://help.tableau.com/current/api/vizql-data-service/en-us/docs/vds_limitations.html)); and per-persona captures for row-level security. Harvesting it is the one step that cannot be redone after decommissioning.

Two infrastructure facts shape the design. **Every .hyper file must pass through Tableau's closed `hyperd` engine at least once**, so the right policy is to convert once into Parquet and Iceberg, persist each extract's recipe (filters, aggregation, incremental key) without re-applying filters already baked into the data, and replay incremental keys with Iceberg `MERGE` on Athena engine v3 ([Athena MERGE](https://docs.aws.amazon.com/athena/latest/ug/merge-into-statement.html)). Many extracts are snapshots of warehouse tables, and re-pointing those to a live Redshift or Athena source avoids moving data at all. Legacy .tde files cannot be opened by Desktop after 2024.2 ([Extract upgrade](https://help.tableau.com/current/pro/desktop/en-us/extracting_upgrade.htm)) and Tableau's own conversion sample relies on an undocumented reader pinned to a 2023 build ([tde-to-hyper](https://github.com/tableau/hyper-api-samples/tree/main/Community-Supported/tde-to-hyper)), so refreshing extracts on the Server before download is safer. Second, **Athena caps active DML queries at 200 in us-east-1, counting queued queries** ([Athena quotas](https://docs.aws.amazon.com/general/latest/gr/athena.html)): fifty users opening eight-tile dashboards at once already exceed it, Athena's own result reuse matches only exact repeats and switches off on tables under Lake Formation fine-grained access ([Athena result reuse](https://docs.aws.amazon.com/athena/latest/ug/reusing-query-results.html)), and Redshift Serverless bills a 60-second minimum per query ([Redshift 4-RPU](https://aws.amazon.com/blogs/big-data/amazon-redshift-serverless-at-4-rpus-high-value-analytics-at-low-cost)). A semantic-layer cache and pre-aggregations are mandatory, not an optimization.

AI-authored dashboards are executable code produced by a model that reads untrusted data such as column names, comments and cell values. The defensible pattern is already standardized: MCP Apps renders UIs in host-sandboxed iframes, builds the content security policy from declared domains and talks JSON-RPC over `postMessage` ([MCP Apps spec](https://github.com/modelcontextprotocol/ext-apps/blob/main/specification/2026-01-26/apps.mdx)), and Lightdash proxies every query from its sandboxed apps ([Lightdash architecture](https://github.com/lightdash/lightdash/blob/HEAD/docs/data-apps.md)). Agent sandboxes need equal care, because headless `claude -p` without `--bare` runs a project's hooks and connects its `.mcp.json` servers "even in a folder you've never trusted" ([Claude Code headless](https://code.claude.com/docs/en/headless)), and Metabase's November 2026 MCP post-mortem concedes that fencing untrusted data "doesn't guarantee" safety, leaving permission scoping as the real limit on damage ([Metabase](https://www.metabase.com/blog/mcp-tool-design-lessons)).

| Hard problem | Why naive conversion fails | Mitigation |
|---|---|---|
| LOD expressions and filter order | FIXED runs before dimension filters unless they are context filters; INCLUDE/EXCLUDE run after; join plans are undocumented | Staged-CTE planner with null-safe joins; golden LOD workbooks checked against Server CSVs and VDS |
| Table calculations | Depend on view layout, addressing and densification; defaults undocumented | SQL windows for static partitions; client-side reference engine otherwise; diff both against Query View Data |
| Dates, types and NULLs | Float division, INT truncation, IIF versus IF NULL routing, week start, boundary-counting DATEDIFF, fiscal years | Explicit CASE templates; TDVT suites on Athena and Redshift in CI |
| Relationships and blending | Native-grain aggregation, join culling, post-aggregation left joins with `*` for mixed values | Per-object pre-aggregation; blends as a post-join of two result sets |
| Row-level security | Four Tableau RLS styles; user functions resolve to the wrong identity if pushed to the engine | Session-bound predicates injected by the query service; impersonated per-persona captures as tests |
| Custom SQL, RAWSQL and regex | Source-dialect SQL; ICU versus Java versus POSIX regex | sqlglot transpiling, EXPLAIN validation, human or Claude review queue |
| Visual semantics | Automatic marks undocumented; nested crosstabs; geocoding; floating layouts | Spec with explicit "unsupported" flags; HTML grids; open boundary data; Tableau PNGs as the AI target |
| XML robustness | Flag-prefixed names, frozen version strings, loader-stripped elements | Normalize names, detect version by `source-build`, raw passthrough, schema as a warning |
| Extracts | Closed engine; .tde unreadable after 2024.2; collations, 128-bit numerics, geography | Convert once; refresh on Server first; row-count and checksum checks after export |
| Concurrency and cost | 200-query Athena cap including queued queries; 60-second Redshift minimum | Pre-aggregations and a cache keyed on query, RLS context and data version |
| AI-generated code | Prompt injection through data; exfiltration | Sandboxed iframes with no network access; agent egress only to Bedrock and MCP; user-scoped tokens; human-confirmed publish |

The four RLS styles in the table are manual user filters, dynamic user-function calculations over entitlement tables, virtual-connection data policies and database-native security driven by Initial SQL ([RLS options](https://help.tableau.com/current/server/en-us/rls_options_overview.htm)).

## The name, the license and Tableau's roadmap carry the non-technical risk

**"TabFree" should be renamed before any public release.** Salesforce's trademark guidelines explicitly cover Tableau and forbid incorporating "any recognizable portion" of its marks into a product, company or domain name, forbid "abbreviations or translations" of those marks, and cite "www.tableauapp.com" as a prohibited example ([Salesforce trademark guidelines](https://www.salesforce.com/company/legal/tmcusageguidelines/)). A product positioned as a free Tableau replacement makes "Tab-" read as exactly such an abbreviation. A Trademarkia search found no "tabfree" registrations ([Trademarkia](https://www.trademarkia.com/search/trademarks?q=tabfree)), but that does not lower the risk, which comes from Tableau's marks rather than from a rival TabFree mark; tabfree.com has been registered since 2005, while WHOIS found no registration for the .io, .org or .ai names (re-verify at [ICANN Lookup](https://lookup.icann.org)). The safe pattern is a distinct name; plain-text nominative claims such as "imports Tableau workbooks" or "migrate from Tableau Server", always less prominent than the product name and followed by the attribution "Tableau is a trademark of Salesforce, Inc."; no Tableau logos or trade dress; neutral component names (a "hyper-to-iceberg" converter, not a "Tableau converter"); and a professional clearance search in Nice classes 9 and 42 before domains are registered. None of this is legal advice, and counsel should review the final name.

**Apache-2.0 is the right project license.** It matches Superset, Cube, OpenFGA and the Hyper API, carries the explicit patent grant enterprises expect, and leaves room for a separately licensed `ee/` directory later, as Lightdash has done ([Lightdash license](https://github.com/lightdash/lightdash/blob/HEAD/LICENSE)). AGPL would deter embedders and integrators, and forking an AGPL platform such as Metabase would make TabFree AGPL while still leaving its paywalled governance features to rebuild ([Metabase license](https://github.com/metabase/metabase/blob/HEAD/LICENSE.txt)). Two dependencies need care. The Hyper API's native `hyperd` binary ships inside a wheel licensed Apache-2.0, so the NOTICE must be retained and each new wheel's bundled license rechecked ([PyPI tableauhyperapi](https://pypi.org/project/tableauhyperapi/)). The TypeScript Claude Agent SDK is governed by Anthropic's Commercial Terms of Service rather than an OSI license, while the Python SDK repository is MIT ([TypeScript SDK](https://github.com/anthropics/claude-agent-sdk-typescript)) ([Python SDK](https://github.com/anthropics/claude-agent-sdk-python)); AI authoring should therefore be an optional, pluggable module whose operators accept Anthropic or AWS Bedrock terms when they enable it. AG Grid's enterprise package is commercially licensed and should stay out of the dependency tree ([AG Grid](https://github.com/ag-grid/ag-grid)).

**Tableau's roadmap is the main strategic risk.** Data Apps, Studio and the authoring MCP tools mean Tableau will keep improving the experience TabFree promises, and customers content to buy Tableau+ get it without migrating. TabFree's durable advantages are the ones Tableau cannot match without undercutting its own pricing: no license fees, data in open Iceberg tables in the customer's AWS account, and dashboards as portable code. The likeliest early adopters are self-hosted Tableau Server shops already on AWS with large Viewer populations and no Salesforce CRM, for whom every existing converter points toward Fabric, Quick Sight, Databricks, Snowflake or Sigma rather than a vendor-neutral, self-hosted destination; that profile is an inference, because no independent survey of why organizations leave Tableau exists.

## A thin governed core, a JSON spec and an owned compiler anchor the build

**Build a thin new governed core rather than extending Superset, and confirm the call with a short spike.** The case for Superset deserves a fair hearing: it would hand TabFree authentication, roles, row-level security, scheduled PDF reports, guest-token embedding, an RBAC-aware MCP server, a Helm chart and a 75,000-star ASF community on day one, plus Preset's working conversion skill, and its `.supx` extensions promise new features "without modifying the core codebase" ([Superset extensions](https://github.com/apache/superset/blob/HEAD/docs/developer_docs/extensions/overview.md)). But TabFree's P0 contract is precisely what Superset lacks. Tableau's capability-level allow/deny rules, project defaults, locked nested projects and site-role ceilings would have to be layered onto Superset's Admin/Alpha/Gamma role model ([Superset security](https://github.com/apache/superset/blob/HEAD/docs/admin_docs/security/security.mdx)); AI-authored TabFree dashboards would form a parallel content model beside Superset's native chart grids; SAML is not documented natively; and the irreducible work—the Tableau-semantics compiler, the migrator, the parity harness and the authoring MCP server—must be built either way. The spike should answer two falsifiable questions: can a `.supx` extension host a sandboxed spec-dashboard content type whose queries proxy through Superset's data API, and can Superset's roles pass a Tableau effective-permission test matrix without forking? If both pass, extend Superset; if either fails, compose the core from Fargate services, Aurora PostgreSQL, an authorization engine and Cube.

**Make the dashboard artifact a governed JSON spec, with sandboxed HTML/JS widgets as the escape hatch.** Claude Code still authors it and the runtime still renders HTML, so the brief's AI-authored web dashboards survive intact. What changes is that the artifact can be schema-validated, compiled deterministically from a .twb, edited through small operation lists instead of whole-file rewrites, rendered identically by the PDF subscription service, and restricted to semantic queries, so data access is RLS-correct by construction. Grafana's MCP server patches dashboards "without requiring the full JSON" ([mcp-grafana](https://github.com/grafana/mcp-grafana)) and Metabase applies dashboard edits as transactional operation lists with a `validate_only` preview ([Metabase](https://www.metabase.com/blog/mcp-tool-design-lessons))—the token-efficient edit model that on-the-fly user changes need. Lightdash and Tableau chose raw source code instead, which buys unlimited flexibility, but both then had to wrap it in sandboxes and query proxies, and Lightdash's data apps still carry visible costs: a browser-only runtime, 500-row result pages and image-based PDF export ([Lightdash docs](https://docs.lightdash.com/data-apps)). Inside the spec, Vega-Lite should be the default grammar because it is JSON-schema-validated, declares cross-filter selections inline and mirrors Tableau's shelf model ([Vega-Lite selections](https://vega.github.io/vega-lite/docs/selection.html)); ECharts covers the chart types and volumes Vega-Lite handles poorly, provided its option objects are stripped of JavaScript formatter functions; Perspective handles pivots; and dbt Labs' agent-oriented dashboard YAML is a useful design reference ([dbt-charts](https://github.com/dbt-labs/dbt-charts)). No head-to-head study of LLM reliability across chart grammars exists, and one Vega-Lite evaluation found "substantial performance disparities across prompt strategies, chart types, and LLMs" ([arXiv 2401.11255](https://arxiv.org/abs/2401.11255v1)), so the team should run its own spec-validity eval before locking the grammar.

**Own the Tableau-semantics compiler and borrow the execution layer.** The compiler is TabFree's core intellectual property: the official grammar parses formulas into a typed AST, a planner emits staged CTEs that follow Tableau's order of operations, and sqlglot, which already ships `athena`, `trino` and `redshift` dialects and reads `tsql`, `oracle` and `snowflake` for custom SQL and RAWSQL, renders the result ([sqlglot dialects](https://github.com/tobymao/sqlglot/tree/main/sqlglot/dialects)). A connection-remapping registry rewrites each Tableau relation to a Glue or Redshift table, and published-data-source references resolve to the migrated semantic model. Dashboards reference stable query IDs and bind parameters through a governed query service, so Claude never writes SQL. One choice worth making deliberately: keeping Tableau's formula syntax as TabFree's user-facing calculation language preserves migrated calculations verbatim, keeps analysts' skills useful, and forces every Claude edit through the same compiler and conformance tests. For execution, **Cube Core is the only candidate with maintained Athena and Redshift drivers, a pre-aggregation store and declarative row-level policies in one Apache-2.0 package** ([Cube](https://github.com/cube-js/cube)) ([Cube data access policies](https://cube.dev/docs/product/auth/data-access-policies)). dbt MetricFlow became Apache-2.0 in October 2025 but brings no cache or row-level security ([dbt Labs](https://www.getdbt.com/blog/dbt-labs-affirms-commitment-to-open-semantic-interchange-by-open-sourcing-metricflow)), Malloy has no Athena or Redshift dialect ([Malloy](https://github.com/malloydata/malloy)), and Ibis has no Redshift backend ([Ibis backends](https://github.com/ibis-project/ibis/tree/main/ibis/backends)). Whether Cube can host staged LOD plans is unverified, so a spike must decide whether compiled SQL runs through Cube or through the governed service directly, with Cube still handling caching and policies. Apache Ossie, in the ASF Incubator since June 2026, should be the import and export format rather than the runtime model while its spec incubates ([Techzine](https://www.techzine.eu/news/data-management/144719/microsoft-and-google-to-contribute-to-the-apache-ossie-project/)); Tableau says it contributed a semantic translator to the project, but whether that covers classic .tds files is unknown ([Tableau blog](https://www.tableau.com/blog/alliance-to-apache-next-chapter-for-open-semantics)).

**Land extracts as Iceberg tables, default to Athena, and use Redshift Serverless for live and hot sources.** Athena costs $5 per terabyte scanned and nothing when idle ([Athena pricing](https://aws.amazon.com/athena/pricing/)), Iceberg tables on Athena support `OPTIMIZE` compaction and `VACUUM` alongside transactional `MERGE` ([Athena Iceberg optimization](https://docs.aws.amazon.com/athena/latest/ug/querying-iceberg-data-optimization.html)), and one Athena workgroup per TabFree site isolates cost. Redshift Serverless starts at $1.50 per active hour at its 4-RPU minimum and wins on concurrency, joins and sub-second repeats thanks to its result cache and auto-refreshing materialized views ([Redshift pricing](https://aws.amazon.com/redshift/pricing/)) ([Redshift MV rewrite](https://docs.aws.amazon.com/redshift/latest/dg/materialized-view-auto-rewrite.html)), but its 60-second minimum makes sporadic traffic expensive without a warm cache in front. Row-level security should be enforced in the application, with the semantic layer injecting predicates from the viewer's session, because Lake Formation fine-grained access needs per-user identities at query time and disables Athena result reuse ([Athena result reuse](https://docs.aws.amazon.com/athena/latest/ug/reusing-query-results.html)); Lake Formation data filters and Redshift RLS policies remain useful as defense in depth for hard tenant boundaries ([Lake Formation](https://docs.aws.amazon.com/lake-formation/latest/dg/data-filtering.html)) ([Redshift RLS](https://docs.aws.amazon.com/redshift/latest/dg/t_rls.html)). No public benchmark compares p95 latency for small aggregate queries on the two engines, so measurements on representative extracts should settle the split per data source.

**Model authorization as relationships and test it against Tableau's semantics.** OpenFGA (Apache-2.0, CNCF incubating since October 2025) fits the nested site, project and content hierarchy and offers a list-objects call for permission-filtered browse and search ([OpenFGA](https://github.com/openfga/openfga)) ([CNCF](https://www.cncf.io/blog/2025/11/11/openfga-becomes-a-cncf-incubating-project/)). Cedar (Apache-2.0, CNCF sandbox) runs embedded with no network hop and expresses denials natively through `forbid`, and unshackle already emits Cedar policies ([Cedar](https://aws.amazon.com/blogs/opensource/cedar-joins-cncf-as-a-sandbox-project)). Amazon Verified Permissions would add $5 per million checks and AWS lock-in ([AVP pricing](https://aws.amazon.com/verified-permissions/pricing/)). The deciding test is a Tableau effective-permission matrix covering user versus group rules, locked and nested projects, site-role ceilings, owners and project leaders. For identity, Cognito brokers OIDC and SAML at $0.015 per federated monthly active user beyond 50 ([Cognito pricing](https://aws.amazon.com/cognito/pricing/)) and Keycloak's SCIM API became fully supported in release 26.8 ([Keycloak 26.8](https://www.keycloak.org/2026/10/keycloak-2680-released)); because Cognito documents no SCIM support and groups drive permissions, TabFree should own its SCIM 2.0 endpoint. Embedding should mirror Tableau's connected apps—short-lived JWTs valid for at most ten minutes, single-use IDs, scopes and user-attribute claims—so portal owners can switch with minimal rework ([Tableau connected apps](https://docs.salesforce.com/tableau/current/en-us/online/connected_apps_direct.md)).

**Run each authoring session as a sandboxed Claude agent acting as the user, behind a single MCP surface.** The Claude Agent SDK packages Claude Code as a library; Anthropic suggests roughly 1 CPU, 1 GiB of memory and 5 GiB of disk per agent and notes that token cost "typically dominates container infrastructure cost by an order of magnitude or more" ([Agent SDK hosting](https://code.claude.com/docs/en/agent-sdk/hosting)). Each session should run in its own Fargate task with no route out except to Bedrock and the TabFree MCP endpoint, with settings sources, auto-memory, web tools and general shell access disabled, following Anthropic's hardening guidance ([secure deployment](https://code.claude.com/docs/en/agent-sdk/secure-deployment)); quick "make this stacked" edits can use a lighter Messages API tool loop inside the API service. Claude in Amazon Bedrock runs "with zero operator access" and offers regional endpoints at a 10% premium, but lacks the Files API, server-side tools, the MCP connector and Managed Agents ([Claude in Amazon Bedrock](https://platform.claude.com/docs/en/build-with-claude/claude-in-amazon-bedrock)). The TabFree MCP server should encode what Tableau, Grafana, Superset and Metabase have learned: per-user OAuth so every call is authorized and RLS-filtered as the requesting user ([tableau-mcp](https://github.com/tableau/tableau-mcp)); summaries before full documents; query handles instead of retyped state; operation-based patches with `validate_only`; two-phase destructive actions in the style of Tableau's `delete-content` and `confirm-delete-content` pair ([toolName.ts](https://github.com/tableau/tableau-mcp/blob/main/src/tools/web/toolName.ts)); archiving instead of deletion; fenced untrusted data; no raw SQL without a separate capability; and rate limits at the gateway, since Superset's MCP server applies none of its own ([Superset MCP](https://superset.apache.org/admin-docs/configuration/mcp-server)). Every save becomes an immutable revision recording author type, agent session and validation results, and per-project policies can require human approval before agent-authored revisions publish.

A bottom-up model built from us-east-1 list prices puts infrastructure at roughly **$250–350 a month for 50 users and about $1,400 a month for 1,000 users** on the Athena path, with Claude tokens adding about $150–450 and $1,400–2,900 respectively at Sonnet 5.5 to Opus 5.5 rates ([Fargate pricing](https://aws.amazon.com/fargate/pricing/)) ([Aurora pricing](https://aws.amazon.com/rds/aurora/pricing/)) ([Athena pricing](https://aws.amazon.com/athena/pricing/)) ([Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing)). The model's assumptions about authoring sessions, tokens per session and cache hit rates are unvalidated, but its shape holds: tokens, not servers, are the largest variable cost of AI authoring, and NAT gateways, load balancers and the database floor dominate small installations. Optional Redshift Serverless for live sources adds roughly $800 a month at the larger size ([Redshift pricing](https://aws.amazon.com/redshift/pricing/)). For scale, 1,000 Viewer seats alone cost $15,000–35,000 a month at Tableau's reported list prices ([datastudios](https://www.datastudios.org/post/tableau-pricing-creator-explorer-viewer-standard-enterprise-tableau-plus)).

The build should advance through gates rather than dates, because no credible effort data exists; the only published benchmarks, 1.5–3 months for 20–50 dashboards and 6–12 months for 150–500, come from a migration vendor ([Lets-Viz](https://lets-viz.com/blogs/tableau-to-power-bi-migration-guide)). **Phase 0, census and decisions,** renames the project, adopts Apache-2.0, runs the read-only crawler to produce an inventory, a dependency graph and usage-weighted complexity scores, counts every construct in every .twb, starts harvesting ground truth for in-use views, and runs four spikes: Superset versus a thin core, Cube's ability to host staged LOD SQL, Athena versus Redshift latency on real extracts, and a chart-spec authoring eval. It exits when each decision is recorded and the P0 backlog is sized from the census rather than from vendor rubrics. **Phase 1, governed core and data plane,** delivers identity, the content tree, the effective-permission engine, the RLS policy model, the extract-to-Iceberg pipeline, the compiler for P0 semantics passing TDVT on both engines, a deterministic converter for P0 constructs, the spec renderer for P0 visuals with filter and highlight actions, the cache, exports, subscriptions, refresh schedules, audit logging and backup. It exits when the most-used dashboards show zero data diffs and pass a visual threshold against harvested ground truth, and when RLS persona captures match.

**Phase 2, AI authoring and bulk migration,** opens the MCP server and per-session agents to users with revision history and approval policies, scales conversion through the deterministic-plus-Claude-repair loop, migrates user state (custom views, favorites, subscriptions, and alerts pre-filled for owners to confirm where conditions cannot be decoded), and adds redirects from old Tableau URLs. It exits when every in-use dashboard is accounted for—converted with parity, rebuilt, or retired—and both systems have run side by side. **Phase 3, P1 parity and decommission,** adds sets and set actions, parameter actions, dynamic zone visibility, viz in tooltip, device layouts, data-driven alerts, embedding, admin usage analytics, multiple sites, incremental refresh and MCP Apps rendering inside Claude; an optional Tableau-REST-compatible shim, which has no precedent anywhere, would keep existing tabcmd and TSC scripts working. Tableau Server is switched off only after its ground truth is archived.

## Conclusion

TabFree's defensible core is not AI authoring, which Tableau, Lightdash, Sigma, Snowflake and Databricks all ship in some form, but **fidelity**: an open compiler that makes Athena and Redshift return Tableau's numbers, an engine that reproduces Tableau's effective access, and a conformance corpus that proves both. The ecosystem shows why this is worth doing in the open. Dozens of young converters each re-solve the same parsing and translation problem for a different proprietary target, and none publishes results beyond a handful of samples. Released as standalone Apache-2.0 libraries with TDVT pass rates attached, the compiler and conformance suite could become the shared foundation those projects lack—a stronger position than racing Tableau on authoring features it is already shipping, and one that makes TabFree's own migration claims verifiable.

The brief's goal of migrating every dashboard is better framed as accounting for every dashboard: retire what nobody opens, convert what the compiler handles with parity proven, have Claude rebuild the rest against captured screenshots and numbers, and redesign the long tail. That reframing moves the critical path. The irreversible tasks are not writing the server but harvesting ground truth—renders, summary data, calculation oracles and per-persona RLS captures—while Tableau Server still runs, and choosing a name that will not draw a trademark complaint in the week the project launches.
